# S2.3 — Per-Axis Resolution Migration (un-cubic-forcing)

**Status:** SCOPED, NOT STARTED. **Scope: 105 cubic-assumption sites, 57 crash-if-missed.** A cross-crate
refactor (`core_math` + `app` + `graphics` + `render`). **Do NOT attempt as a session-tail task or one-shot.**
Full site list: workflow `w1fgf5r0a` (2026-06-28 audit), 4 agents, exhaustive.

## Why (and why it's optional)
Today GridBacked bakes are FORCED cubic (`bake_dispatch.rs:512-519` → `[max_axis;3]`) because the DC path
assumes a perfect cube: `accept_gpu_result` infers resolution via `cbrt(grid.len())`, and `FlatGridAccessor`
/ `sdf_mesh.wgsl` index with a single `nverts` on all 3 axes. An asymmetric grid + that inference = the DC
walks a `cbrt(rx·ry·rz)³` cube that overruns the packed buffer → **OOB crash** (this is the DUPCRASH the
forcing prevents). The forcing is CORRECT and crash-safe; the only cost is memory: an elongated 256×64×64
body bakes 256³ (~16× the voxels it needs). **This is a perf win for ELONGATED bodies only — a bug fix it is
NOT** (the cubic forcing makes every grid cubic, so the "partial-bake OOB" the GATE-2 audit feared cannot occur).

## The change (CLAUDE.md R8 — carry resolution explicitly, never re-derive from buffer length)
Thread `[rx,ry,rz]` from `PendingBake.resolution` (already `[u32;3]`) through the whole path; remove the cbrt
inference and the cubic-forcing. Root data-type changes (these break ~50 callers at once — the big-bang):
- `BodyCacheEntry.bake_resolution`, `RamCacheEntry.bake_resolution`, `BodyBakeResult.bake_resolution`,
  `PendingFullUpload.resolution`, `last_upload_key.1`, `VolumePoolSlot.resolution`, `SdfBodyMeshSlot.res`:
  `u32 → [u32;3]` (`mod.rs:103/116/133/344/214`, `gpu_volume.rs:479`, `sdf_gpu_mesh.rs:439`).
- `body_grid()` return tuple `.1`: `u32 → [u32;3]` (`mod.rs:852`).
- `accept_gpu_result(... )`: add `resolution: [u32;3]` param (drop `cbrt` at `bake_readback.rs:141`).
- `sdf_populate_resident`/`gpu_mesh_to_cache`/`request_mesh_from_grid` params: `nverts: u32 → res3: [u32;3]`.
- `DcGridConfig.nverts → resolution: [u32;3]` (`mesh.rs:336`); `FlatGridAccessor`/`BrickGridAccessor`/
  `VolumeAccessor::nverts()→nverts_xyz()` (`chunked_dc.rs`); `ChunkedMesh.{grid_resolution,chunks_per_axis}→[u32;3]`.
- GPU: add `res: vec4<u32>` to WGSL `DcParams` + Rust `DcParamsGpu` (replace `res()` reading `a0.w` with
  `resx/resy/resz`); per-axis `cell_world`/`world_to_grid`/`vox`/`fld` Z-stride `rx*ry`; `dc_caps(res:[u32;3])`;
  `encode_dc_passes(cells:[u32;3])` → per-axis `dispatch_workgroups`.
