**Step B — Build the projection: `Vec<PolyModifier>` → chain DAG.** Add `fn build_dag(node_id, &[PolyModifier]) -> PolyDag` that maps the linear modifier stack to a chain DAG trivially (each modifier = one node, input = previous node's output, root input = the body's base `Arc<HalfEdgeMesh>`/`PolyMesh`). **Step C — Per-node eval cache keyed on `(input topo_gen, param hash)`.** Each node caches its output `PolyMesh` + the `(input_topo_gen, param_hash)` it was computed for. `eval(node)` returns the cache when the key matches; recomputes (and bumps its own output `topo_gen`) only on mismatch. Param hash is computed from the node's `MeshOp::Params` (stable hash; document determinism). This is the LAZY-EVAL CORE — a param change on node K re-evals K and everything downstream, nothing upstream. Build + test.

**Step D — Lazy invalidation from the changed node forward.** On a modifier param-edit / add / remove / reorder (inside the existing `transaction()`/episode), invalidate the affected node's cache and let the key-mismatch cascade downstream. NO full-chain recompute on an unchanged param; NO timing/frame-skip — invalidation is structural via the key. A reorder/insert/delete must re-key correctly (stable identity, not Vec position). Build + test.

**Step E — Frame-budgeted eval in `poll_background_tasks` with an explicit cap.** Drive DAG eval + `to_raster_data` upload from `poll_background_tasks`/scope-leave (never panels). Add a NEW `const MAX_POLY_DAG_EVAL_PER_FRAME` (or equivalently-named) cap, documented in a comment BESIDE the existing bake/DC/mesh caps you found in Step 0. The re-evaluated display mesh invalidates its `mesh_cache` bind group via the generation counter. Bind-group creation stays in `viewport_render`; GPU mutation stays in poll. Build `cargo build -p app`.

**Step F — DRAFT-under-interaction via the existing InteractionRenderPolicy latch.** Global/heavy DAG nodes (Subdivide / bevel-all-class) eval at DRAFT resolution while an interaction episode is latched, and re-eval at FULL quality on commit-cooldown — reusing the EXISTING latch the SDF/voxel path uses (found in Step 0).
